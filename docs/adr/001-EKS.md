# ADR-001 — Use Amazon EKS as the Kubernetes Platform

## Status

Accepted

---

## Context

The NexPay platform will be a distributed payment system composed of multiple independent services and workloads.

The architecture requires Kubernetes capabilities to support:

* multiple application services;
* workload replication;
* workload distribution across Availability Zones;
* health checks;
* service discovery;
* automatic workload rescheduling;
* horizontal scaling;
* infrastructure scaling;
* workload isolation;
* resource management;
* controlled deployments;
* automatic workload recovery;
* observability;
* security integration;
* workload identity;
* GitOps;
* progressive delivery;
* resilience and chaos engineering experiments.

The size and complexity of the NexPay architecture require a robust container orchestration platform capable of supporting these requirements as the platform evolves.

Kubernetes is therefore a fundamental part of the NexPay architecture and learning objectives.

---

## Decision

NexPay will use **Kubernetes as its container orchestration platform**, provisioned through **Amazon Elastic Kubernetes Service (EKS)** on AWS.

EKS will be the Kubernetes platform used throughout the laboratory.

The platform will use Kubernetes capabilities for:

* workload orchestration;
* scheduling;
* service discovery;
* workload replication;
* health management;
* horizontal scaling;
* resource management;
* deployment management;
* workload recovery;
* security controls;
* observability;
* GitOps;
* resilience experiments.

The Kubernetes environment will be integrated with the AWS infrastructure required by the NexPay architecture.

---

## Why Kubernetes

Kubernetes provides the orchestration capabilities required to operate a distributed platform composed of multiple services.

Relevant capabilities include:

* scheduling;
* Deployments and ReplicaSets;
* Services;
* readiness and liveness probes;
* horizontal scaling;
* resource requests and limits;
* namespaces;
* RBAC;
* service discovery;
* workload identity;
* node management;
* rolling deployments;
* rollback;
* observability;
* GitOps integration;
* security policies;
* extensibility.

These capabilities will be used both to operate the NexPay platform and to provide practical experience with Kubernetes and Platform Engineering.

---

## Consequences

### Positive

* Kubernetes becomes the core orchestration platform for NexPay;
* managed Kubernetes environment on AWS;
* suitable platform for multiple distributed services;
* deep integration with the AWS ecosystem;
* support for workloads distributed across Availability Zones;
* support for autoscaling;
* support for dynamic node provisioning;
* integration with GitOps;
* support for advanced deployment strategies;
* suitable environment for resilience experiments;
* practical experience with Kubernetes and Platform Engineering.

### Negative

* greater operational complexity than simpler container platforms;
* additional AWS infrastructure costs;
* Kubernetes learning curve;
* larger number of components to observe, secure and operate;
* need to understand both Kubernetes concepts and their integration with AWS.

---

## Architectural Implications

The decision to use Kubernetes through EKS influences several subsequent architectural decisions within NexPay.

Future decisions will need to address areas such as:

* networking;
* ingress;
* load balancing;
* IAM and workload identity;
* secrets management;
* observability;
* autoscaling;
* node provisioning;
* storage;
* service-to-service communication;
* deployment strategies;
* GitOps;
* security policies;
* disaster recovery.

Architecturally significant decisions in these areas will be documented in separate ADRs.

---

## Validation

The Kubernetes platform will be validated through controlled experiments including:

* EKS cluster creation;
* workload deployment;
* workload distribution across Availability Zones;
* health check validation;
* workload rescheduling;
* scaling tests;
* node failure tests;
* pod failure tests;
* application deployments;
* rollback;
* observability;
* AWS service integration;
* chaos engineering experiments.

Observed results will be used to evaluate whether the platform is meeting the requirements defined for NexPay.

---

## Reconsideration

This decision may be revisited if the fundamental requirements of NexPay change.

As long as the current requirements remain valid, **NexPay will use Kubernetes provisioned through Amazon EKS as its container orchestration platform**.
